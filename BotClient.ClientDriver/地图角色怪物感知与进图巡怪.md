# 地图 / 角色 / 怪物感知 + 自动点 NPC 进图巡怪

> 适用：C 方案（嗅探 + 真机客户端驱动）下的 BotClient。
> 结论先行：**这四件事的"读法"与直连模式完全一样**，不需要新写感知代码。
> 嗅探到的帧被 `InjectPacket` 塞进原收包信道，`BotRuntime` 用**原有的** `Handle*` 逻辑解析，
> 已经帮你把状态维护在三个结构里：`CurrentMap` / `Player` / `Dots`。
> 新代码只出现在"操作侧"（点 NPC、选菜单、点怪）。

---

## 一、总览：想知道什么 → 读哪里 → 包从哪来

| 想知道什么 | 读哪个成员 | 数据来自（嗅探到的下行包） | 维护者 |
| --- | --- | --- | --- |
| 当前地图代码 | `rt.CurrentMap` | `SM_CHANGEMAP` / `SM_NEWMAP`（正文就是地图代码） | `HandleNewMap` |
| 地图中文名 | `rt.Player.MapName` | 同上，再经 `MapInfo` 文件映射 | `HandleNewMap` |
| 换图后的落地坐标 | `rt.Player.PosX/PosY` | 换图包 `Param=X, Tag=Y` | `HandleNewMap` |
| 自己/别人的坐标变化 | `rt.Player.PosX/PosY`、`rt.Dots` | `SM_POSTIONMOVE` / `SM_ACTION_RET` | `HandlePosMove` |
| 角色基础信息 | `rt.Player`（`BotPlayerState`） | `SM_LOGON` / `SM_ABILITY` / `SM_SUBABILITY` / `SM_SENDUSERSTATE` / `SM_HEALTHSPELLCHANGED` | `HandleLogon` 等 |
| 视野里的所有对象 | `rt.Dots`（`MapDot`） | `SM_WITHINRANGE`（批量）+ `SM_ITEMSHOW/HIDE` + `SM_FEATURECHANGED` | `HandleWithinRange` 等 |
| 怪物消失 | `rt.Dots` 条目被移除 | `SM_DISAPPEAR` / `SM_CLEAROBJECTS` | `HandleDisappear` / `HandleClearObjects` |
| 换图事件通知 | `rt.MapChanged` 事件 | 上面两条换图包 | `HandleNewMap` |

关键数据结构（`BotRuntime.cs`）：

```csharp
public readonly record struct MapDot(long Id, int X, int Y, DotKind Kind, string Name, int Feature = 0);
public enum DotKind { Self, Monster, Npc, Player, Item, Gold }

public readonly BotPlayerState Player = new();
public readonly ConcurrentDictionary<long, MapDot> Dots = new();
public readonly ConcurrentDictionary<long, string> DotNameCache = new();   // 对象 ID → 名字
public string CurrentMap = string.Empty;
public event Action? MapChanged;
```

## 二、当前人物所在地图

三段信息，分别有明确来源：

| 要什么 | 表达式 | 说明 |
| --- | --- | --- |
| 地图代码 | `rt.CurrentMap` | 就是服务端下发的字符串（如 `0` / `0101`），直接用于流程判断 |
| 中文地图名 | `rt.Player.MapName` | `HandleNewMap` 里用 `MapInfoFile.TryLoad()` 把代码翻成中文；**读不到时回退成代码本身**，不要假设一定是中文 |
| 是否换了图 | `rt.MapChanged` 事件 / 比对 `CurrentMap` 前后值 | 传送流程、巡怪换点都靠它 |

换图时**同时**发生三件事（都在 `HandleNewMap` 里，无需你干预）：

1. `CurrentMap` 更新，`Player.MapName` 跟着更新；
2. 落地坐标从换图包的 `Param/Tag` 读出来 —— **这条不能省**。否则角色本地坐标还停在旧图，
   新图所有 NPC 都被算成几百格外，于是"同图 + ≤15 格"的上行闸门把商店/仓库/传送的每条包
   静默丢掉，现象是"日志正常、点啥都没反应"；
3. 收到 `SM_CLEAROBJECTS` 时 `Dots` 被清空，新图的物件由随后的 H 系列包重新灌入。

> 判断"新地图视野是否收齐"没有单独的包：靠"`Dots` 在换图后重新出现条目"或
> `UiStateProbe` 的就绪判定（换图包 → 描述包 / 坐标广播恢复 → 自由态）来近似。

## 三、人物角色信息

全部在 `rt.Player`（`BotPlayerState`），字段与来源：

| 字段 | 来源包 | 备注 |
| --- | --- | --- |
| `Name` | `SM_LOGON` / `SM_USERNAME` | **只在登录那一刻下发**，见第七节坑 1 |
| `Level` / `Job` / 各属性 | `SM_LOGON`、`SM_ABILITY`、`SM_SUBABILITY` | 升级/加点后由 `SM_LEVELUP`、`SM_SUBABILITY` 刷新 |
| `Hp` / `Mp` / 上限 | `SM_HEALTHSPELLCHANGED`、`SM_SENDUSERSTATE`、`SM_STRUCK` | 喝药、被打、升级都会刷新 |
| `PosX` / `PosY` / `Dir` | `SM_POSTIONMOVE`、`SM_ACTION_RET`、换图包 | **这是唯一可信的坐标源**（嗅探得来） |
| `MapName` | `SM_CHANGEMAP` / `SM_NEWMAP` | 见第二节 |

要点：

- **不要自己维护一份坐标**。C 方案下真值来自服务端广播，且必须关掉 `SendWalkAsync` 里的
  "乐观坐标更新"（`CorePatch.md` §3 已说明），否则本地坐标先跳到目标格，
  `MapWalkController` 会误判"已到达"而停止推进，角色一步没动。
- **自身识别**：`rt.MyRecogId` 用来在 `Dots` 里认自己（`DotKind.Self`）。
  它同样来自登录流，是坑 1 的连带受害者。
- 挂在身上的增益/诅咒看 `SM_CHARSTATUSCHANGED`（`HandleCharStatusChanged`）。

## 四、怪物（以及 NPC / 玩家 / 地面物品）

**唯一入口**：遍历 `rt.Dots`，按 `Kind` 过滤。

```csharp
// 视野内所有怪物
var monsters = rt.Dots.Values.Where(d => d.Kind == DotKind.Monster).ToList();

// 最近的怪物（AI 内部就是这么找的：BotCombatAI.FindNearestMonster）
var me = (rt.Player.PosX, rt.Player.PosY);
var nearest = monsters.OrderBy(d => Math.Max(Math.Abs(d.X - me.PosX), Math.Abs(d.Y - me.PosY))).FirstOrDefault();

// 传送员 / 商人
var npcs = rt.Dots.Values.Where(d => d.Kind == DotKind.Npc).ToList();

// 地面掉落
var drops = rt.Dots.Values.Where(d => d.Kind is DotKind.Item or DotKind.Gold).ToList();
```

**类型是怎么定出来的**（别自己用外观去猜）：`HandleWithinRange` 里按 `Feature` 判定，
判据来自原版客户端 `MerchantDialogSystem.TryPickMerchantNpcAtCell`：

| 判据 | 结果 |
| --- | --- |
| `FeatureCodec.Race(feature) == RCC_MERCHANT(50)` | **商人 / 可对话 NPC** |
| `race == 0` | 玩家 |
| 其他 race（如 11、12） | **怪物** |

两个已踩过的坑（源码注释里带真机证据）：

- **不能用 `wAppr` 外观编号区分商人和动物**：`Npcs.txt` 会用配置覆盖商人的 `wAppr`，
  而动物的 `wAppr` 也是数据库外观号，两者数值重叠。
- **动物（鸡/鹿/羊）的 `RaceImg = 11`，恰好等于 `RC_GUARD` 常量值**，
  在本服必须判为怪物，不能按"卫士"对待。

名字：`MapDot.Name` 优先，缺了再查 `DotNameCache`（换图 `Dots` 清空后，
服务端不重发 `WITHINRANGE`，靠 ID 不变的特性复用旧名字，避免列表显示成 `#数字`）。

## 五、自动点 NPC 进图

换图有**两条互不相干**的路，先选对：

| 方式 | 触发 | 代码 | 适用 |
| --- | --- | --- | --- |
| 走门点 | 走到地图连通格上 | 脚本 `DoorToDoorAsync(mapA,x1,y1, mapB,x2,y2, fight)` | 地图边界/洞口类换图，**不涉及 NPC** |
| NPC 传送 | 点传送员 → 选菜单 | `NpcTransferRunner.TransferAsync(npcX, npcY, menuTexts)` | 传送员、车夫、传送阵 NPC |

### 5.1 NPC 传送链（六步，任何一步都不能跳）

```
① 靠近：算切比雪夫距离，> InteractRange-3 就继续靠近（默认闸门 15 格）
② 点 NPC：ClientActionIntent{ NpcInteract, X=npcX, Y=npcY }
③ 等对话态：UiStateProbe 收到 SM_MERCHANTSAY → NpcDialog
  ③b 等菜单文本到齐（1.5s 上限）—— 拿不到就中止，绝不盲点行号
④ 逐级选菜单：DialogSelect{ Text="传送" }、再 DialogSelect{ Text="比奇省" }
⑤ 等换图包：UiStateProbe 收到 SM_CHANGEMAP → MapLoading（此期间所有点击被拦住）
⑥ 等就绪：描述包/坐标广播恢复 → Free，再额外等 MapLoadGuardMs
```

调用示例：

```csharp
bool ok = await host.Transfer.TransferAsync(
    npcX: 330, npcY: 330,
    menuTexts: new[] { "传送", "比奇省" },
    ct);
```

**15 格闸门是硬约束**：服务端对"同图 + ≤15 格"以外的 NPC 交互上行直接静默丢弃
（`BotRuntime` 注释里有 2026-09-23 真机探针的结论）。所以先靠近、再点，顺序不能反。

### 5.2 菜单为什么必须按文本选

`<买/@buy> 武器` 这种序列化正文由 Core 的 `NpcDialogOptions.Parse` 解成
`(显示文本 → 回传命令)` 列表，**顺序与对话框行号一一对应**。
行号会随首页/翻页变化，文本不会 —— 所以 `DialogSelect` 优先用文本匹配。

文本的来源只有一条链路，**必须接通**：

```
SM_MERCHANTSAY → BotRuntime.HandleMerchantSay → NpcMessage 事件
        → host.FeedNpcDialog(id, text) → UiStateProbe.DialogOptions / DialogLines
        → ClientActionDriver.SelectDialogAsync 按文本定位行号
```

宿主侧接线（`CorePatch.md` §4 已加）：

```csharp
runtime.NpcMessage    += (id, text) => host.FeedNpcDialog(id, text);
runtime.SystemMessage += text       => host.FeedSystemMessage(text);   // 仅续期对话态
```

**漏接的后果**（本轮已加固为"拒绝执行"而不是"瞎点"）：

- `DialogLines` 为空 → `SelectDialogAsync` 直接返回并记日志
  `菜单文本为空（宿主是否漏了 NpcMessage → FeedNpcDialog 转发？），拒绝盲点`；
- 文本没匹配上 → 报当前菜单全文并拒绝点击，**不再退回行号盲点** ——
  点错菜单在真实游戏里就是一次真实的购买/出售/传送。

## 六、巡怪（自动打怪）

巡怪本来就在 Core 里，C 方案下**一行不用改**：

| 能力 | 实现 | 关键参数 |
| --- | --- | --- |
| 自动打怪 | `BotCombatAI` 主循环（`FindNearestMonster` 每轮挑最近怪物） | `Enabled` |
| 固定点挂机 | `FightAtPoint` + `FightPointX/Y` + `FightRange`（默认 12） | 怪出范围就回点 |
| 追怪/换点 | `ChaseCooldownMs`(20s)、`RelocateIntervalMs`(6s)、`RelocateGiveUpTries`(3) | 追不到就换位置 |
| 随机游走巡图 | 脚本 `RandomMoveAsync(map, radius)` / `RandomMoveStopAsync` | radius 2~40 格 |
| 边走边打 | 脚本 `WalkFightingAsync`（`WalkToAsync(..., fight:true)` 内部） | —— |
| 自动喝药 | 背包按 `Potions` 顺序找（默认 太阳水/金创药/魔法药），`HpPotionPercent`(60) / `MpPotionPercent`(40) 触发 | 名字须与本服一致 |
| 自动拾取 | `AutoPickupEnabled` + `ItemFilter` + `PickupThreatRadius`(4) | 身边有怪先打怪 |
| 保命飞 | `EscapeHpPercent`(20) → `Escaped` 事件 | 触发软停机 |

**C 方案下真正要调的只有节流值**：服务端按 `!Setup.txt` 的
`WalkIntervalTime / RunIntervalTime = 490ms`、`HitIntervalTime = 900ms` 做阈值，
超速的上行会被**整包静默丢弃**（零回包，最难查）。所以 `BotCombatAI` 的
`WalkIntervalMs / AttackIntervalMs / PotionIntervalMs` 要按本服值再加 100~200ms 余量，
`ClientDriverConfig` 侧的点击节流与之一致，别比它更快。

一条典型的"进图 + 挂机"串法：

```csharp
// 1. 进图（走门点或点传送员，二选一）
await script.DoorToDoorAsync("0", 330, 330, "0101", 200, 200, fight: false, ct);
// 或 await host.Transfer.TransferAsync(npcX, npcY, new[]{"传送","祖玛寺庙"}, ct);

// 2. 到点后开打
ai.Enabled = true;
ai.FightAtPoint = true;  ai.FightPointX = 200;  ai.FightPointY = 200;  ai.FightRange = 12;

// 3. 想自己巡图而不是守点：关掉 FightAtPoint，交给移动脚本
await script.RandomMoveAsync("0101", 15, ct);
```

## 七、必踩的三个坑

| # | 坑 | 现象 | 对策 |
| --- | --- | --- | --- |
| 1 | **抓包晚于客户端登录** | `Player.Name` / `MyRecogId` 为空、`Dots` 空、地图名是代码 | `SM_LOGON` 与初始视野**只发一次**。必须先 `host.StartSniffing()`，**再启动/登录客户端**；已登进去的只能退出重登 |
| 2 | **没接 NPC 文本转发** | 点 NPC 有对话态但菜单是空的，传送流程中止 | 接 `runtime.NpcMessage → host.FeedNpcDialog`（第五节 5.2） |
| 3 | **乐观坐标没关** | 角色原地不动但日志说"已到达" | `Send*Async` 的分流分支必须在**乐观更新之前** return（`CorePatch.md` §3） |

补充一条观测口径：换图后 `Dots` 会先空后满，**不要**把"空"当成"这里没有怪"——
等 `MapChanged` 之后再等一两个包周期（或等 `UiStateProbe` 回到 `Free`）再判断。
